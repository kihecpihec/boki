# M4 Implementation Plan: Three Graybox Levels and Classroom Arrival

Status: implemented on `feat/m4-graybox`; see [M4 handoff and verification](M4-verification.md) for delivered assets and validation results. Interactive acceptance and Windows checks remain pending. The developer explicitly authorized creation and ownership of all three M4 level scenes. The sequence below records the implementation scope; [M3 handoff and verification](M3-verification.md) describes the starting point.

Deliver the next playable slice: ride through Pohorje, Maribor, and FERI, choose a distinct A/B route in each scene, and reach the shared classroom without repairing scene references. This is M4 in [Architecture §9](../Architecture.md#9-development-milestones).

## Scope and Starting Point

Use Unity **6000.6.7f1**, the existing Input System and URP, M1 movement, M2 combat, and M3 run/route state. Preserve the approved [movement](../Gameplay.md#m1-movement-baseline) and [combat](../Gameplay.md#m2-combat-baseline) baselines. Read [Story §3](../Story.md#3-story-beats-and-script) and [§7](../Story.md#7-location-scope-and-production-shortcuts) for location and branch identity; canonical route connections and lock behavior remain in [Gameplay §2–4](../Gameplay.md#2-branching-route-graph).

Create three short graybox gameplay scenes, each with one shared opening, physically distinct A/B variants, and one shared ending. Connect them through the existing session and finish inside one classroom in the FERI scene. Use primitive geometry, existing player/enemy prefabs through scene instances, readable signs, and restrained lighting. Shorten routes before adding architecture or decoration; the final game's duration targets are not an M4 acceptance requirement.

Normal play continues to use all-false in-memory C unlocks. Keep C entrances visible, correctly locked, and physically blocked. Complete C interiors are optional after the A/B slice works; do not expose unfinished routes as passable or add a player-facing unlock cheat. Preserve the complete canonical C connection rules and snapshot tests.

M5 owns permanent unlock saving and earned milestones. M6 owns ranged enemies, light/battery behavior, Guilt, and the professor fight. XP rewards, upgrades, main menu, intro, ending, traps, functional `POWER OFF` interaction, and PS1/VHS polish are outside this milestone. Classroom arrival is a graybox endpoint, not victory or boss completion. No unlock discovery message should claim progress was saved in M4.

## Implementation Sequence

### 1. Extend Scene Routing Without Breaking M3

`RunState` already models Forest, City, and FERI and supports deterministic Forest/City advancement. `RunSession` currently hardcodes the two M3 test destinations and accepts only Forest advancement. `LevelExit` delegates to its manager and can remain a small scene adapter.

- Add a small explicit destination configuration for Forest entry, City, and FERI. Keep scene routing in `RunSession`, separate from deterministic route rules. Avoid a general scene framework or a second session type.
- Preserve the M3 test scenes' existing Forest-to-City and Retry flow through compatible defaults. Configure the owned M4 entry scene to use the production graybox destinations; a later scene must not overwrite a surviving session's destinations or reset its state.
- Support Forest → City and City → FERI. Require the active level, a living player, and an already selected route. Validate the destination before advancing state, and reject repeated/stale requests while loading.
- Retry and Start New Run from any M4 level must reset the existing session and return to `Level1_Pohorje`, rather than the M3 Forest test scene.
- Retain one HP authority and one persistent session. Carry HP and all existing run fields across both transitions without restoring health or replacing the unlock snapshot.
- Direct City or FERI entry must report missing prerequisites, block route selection and exits, and offer Start New Run into the M4 Forest entry. Do not invent previous choices.
- Keep Forest/City transitions free of persistent milestone writes. Leave a clear integration point for M5 without implementing saving now.

### 2. Establish the Shared Graybox Layout

After ownership is confirmed, assemble each scene in the pinned Editor. Reuse the M3 wiring pattern without modifying its source scenes or prefabs.

- Place a safe spawn, one readable fork, two short playable variants, a reserved blocked C entrance, a merge, and a shared endpoint. Keep the routes physically distinct until their merge.
- Use primitive floor/wall/ramp colliders. Avoid narrow passages, abrupt steps, or mandatory jumps whose landing cannot accommodate the existing CharacterController and camera.
- Prevent riding, jumping, or boosting around gate blockers, across route dividers, or behind exit triggers. Position selection triggers beyond the gate entrance so closing alternatives cannot intersect the player.
- Seal unchosen branches at both ends with opaque primitive barriers. Rear seals stay closed until selection, preventing entry or a view into alternatives from the shared merge.
- Keep terrain boundaries recoverable and avoid lethal pits in this slice. Use solid ground and visible barriers rather than adding a new fall/death system.
- Mark the selected direction and next objective with concise English UI text while preserving established Slovenian location names. Do not add a new route confirmation menu.
- Keep only one camera/AudioListener, directional light, EventSystem, and scene coordinator per scene. Do not persist scene objects with the session.

### 3. Build Pohorje

Create `Level1_Pohorje.unity` as the default M4 new-run entry.

- Shared opening: short safe riding area with movement, jump, and boost prompts, followed by a visible fork.
- A / Strmina: a winding tree/log slalom with more melee pressure. Use cylinders and boxes, keeping pursuit approaches open enough for the existing AI.
- B / Gondola: a wider service route with simple ramps and jumpable obstacles, fewer enemies, and optional pole/cabin silhouettes. No operating gondola or bespoke physics.
- C / Rave tunel: visible blocked tunnel entrance using the canonical persistent-lock message. An interior is not required for acceptance.
- Merge the A/B variants into one exit area. Crossing the exit after choosing loads Maribor once and retains damaged HP.

### 4. Build Maribor

Create `Level2_Maribor.unity` and bind its gates to the carried Forest choice.

- Shared opening: compact street and readable fork, with the actual gate availability supplied by `RouteManager`.
- A / Tabor: street slalom around primitive cars and barricades with small melee groups.
- B / Lent: a visibly different riverbank path and bridge silhouette, with room to steer around obstacles. Use solid boundaries beside decorative water; ranged pressure and battery pickups remain later work.
- C / Podzemni prehod: visible blocked underpass entrance. Show the correct route or persistent lock according to the preceding choice.
- Preserve the intentional first-run forced continuation after Forest B. Geometry and signs must not promise City B is reachable when the route rules forbid it.
- Merge into a shared `FERI →` exit, requiring a living player and City selection before loading FERI once.

### 5. Build FERI and the Shared Classroom

Create `Level3_FERI.unity`, using a stylized exterior and short approach rather than a detailed real building.

- A / Glavni vhod: a short corridor with readable melee encounters.
- B / Dvorišče: an open courtyard leading through a side corridor, with a small melee ambush. Replace stairs with ramps.
- C / Servisni vhod: visible locked technical entrance. The `POWER OFF` panel and its boss modifier remain later work; do not show an actionable but nonfunctional interaction.
- Route all playable variants into the same classroom. Keep space for later professor combat, without implementing a boss or spawning a substitute fight.
- Add a small scene-local arrival trigger beyond the merge. Accept only the living active player after a FERI choice, reject repeated entry, and show a clear message such as `CLASSROOM REACHED — END OF M4 GRAYBOX`.
- Arrival must not advance to a nonexistent fourth scene, reset choices, earn an unlock, or announce victory. Keep Start New Run available; no new run-state phase is needed solely for this marker.
- Keep the approach and endpoint safe from attacks through walls. Boss modifiers and the boss-arena unlock milestone remain M6 and M5 respectively.

### 6. Integrate Combat, HUD, and Editor Helpers

- Use the existing `MeleeEnemy` and `AutoLaser` baseline. The AI pursues directly and does not plan around walls: place enemies in open encounter pockets along their own route. Avoid navigation packages or AI rewrites solely to support complex graybox geometry.
- Keep branch encounter roots inactive until their gate is selected. Activate only the chosen group; unchosen enemies must not move, attack, or register as laser targets. Use preplaced instances rather than a spawning framework.
- Keep active regular enemies within [Gameplay §6](../Gameplay.md#6-content-and-enemy-progression-by-level) caps, counting all scene-active enemies, including those in unselected branches. Prefer a small fixed population; add activation logic only if needed by the actual layout.
- Update the route-status view to include FERI choice and a clear current objective. Reuse HP, `ABSENT`, Retry, Start New Run, and the existing cursor/UI behavior.
- Bind scene-local health and combat coordinators to the existing session; wire every local enemy into death shutdown. Retry must recreate enemies, camera, input, spawn, and cooldowns.
- If a creation helper is useful, add an M4-specific Editor helper that refuses to overwrite existing scenes or save dirty/source scenes. Do not repurpose M3 builders to overwrite delivered content.
- Add an M4 player-build helper with an explicit three-scene list, leaving shared build settings unchanged. Preserve M3's separate test build.

### 7. Inspector Wiring and Import

Required assignments in each owned scene:

- Run bootstrap/configuration: M4 Forest entry, City destination, FERI destination, and initialization that preserves an existing session.
- Route manager: correct level identity, scene player, and route/objective Text.
- Gates: unique route identity, manager, primitive entrance blocker/renderer, rear blocker/renderer, initially inactive encounter root, separate selection trigger, and readable sign. Follow the M3 kinematic Rigidbody/trigger setup verified with the CharacterController.
- Forest/City exits: route manager and a shared trigger beyond the merge. FERI arrival: manager/player validation and endpoint view.
- Player and combat coordinator: session binding enabled, player controls, laser, camera, local enemy references, HP/death view, Retry and Start New Run bindings.
- Geometry: environment layers included in weapon and camera obstruction masks; preserve existing player/enemy filtering. Check low ceilings and camera obstructions in the corridors.
- UI: one Input System EventSystem, readable text at 1280×720, and no decorative collider blocking a trigger or sign.

Import externally created scripts/assets with Unity **6000.6.7f1** so the Editor generates metadata. Preserve all existing GUIDs. If the Editor cannot run, report pending imports and missing `.meta` files explicitly; do not describe the scenes as ready to integrate.
