# M2 Handoff and Verification

Implementation branch: `feat/m2-combat`. Combat and retry are implemented, and the developer confirmed that everything works as intended during manual playtesting. Windows acceptance remains pending. Approved combat rules and tuning live in [Gameplay](../Gameplay.md#m2-combat-baseline). Scope remains in [the M2 plan](M2.md).

## Open and Play

1. Open `Source/Game/` with Unity **6000.6.7f1** and allow compilation/import to finish.
2. Open `Assets/Scenes/Combat_Test.unity` and enter Play Mode.
3. Use the M1 controls: WASD, mouse, Space, and Left Shift. The laser automatically attacks visible enemies. Escape releases the cursor; left click recaptures it during live play. Cursor release is not a combat pause.
4. Ride toward the red melee placeholders to test damage; the wall on the right blocks shots. The laser can kill distant enemies before they reach Boki, so move into a group to test losing HP.
5. At zero HP, check `ABSENT`, then click `Retry`. Health, enemies, spawn, camera, and cooldowns reset.

Four enemies are placed manually. Pursuit uses a CharacterController and direct steering on the flat floor; enemies collide with obstacles but cannot plan a route around them. XP, battery rewards, spawning waves, and full pause behavior are outside M2.

The task owns the new combat scene and enemy prefab. Existing scenes, the shared M1 player prefab, shared input actions, build settings, and package manifests were not changed. M2 player combat components are overrides on the player instance in the new scene.

## Assets and Inspector Assignments

- `Assets/Scripts/Combat/Rules/HealthState.cs`: deterministic HP and one-time death rules, shared by player and enemy health. Its assembly allows independent EditMode tests.
- `Assets/Scripts/Player/PlayerHealth.cs`: scene-local HP and health/death events. M3 must connect this to RunSession without introducing a second health authority.
- `Assets/Scripts/Combat/EnemyHealth.cs`: enabled living-enemy registry, HP, death notification, and removal. No rewards are currently granted.
- `Assets/Scripts/Combat/AutoLaser.cs`: nearest visible enemy selection, pulse damage, cooldown, and one reusable beam. Assigned player health, `LaserOrigin`, and LineRenderer. Environment mask is `Default` only.
- `Assets/Scripts/Enemies/MeleeEnemy.cs`: assigned player target, direct pursuit, gravity, contact distance, and attack interval. Contact attacks also check for an intervening wall.
- `Assets/Prefabs/Enemies/Melee_Test.prefab`: CharacterController, health, melee AI, aim point, and collider-free capsule visual. Assign the player target on each scene instance; the reusable prefab intentionally has no scene target.
- `Assets/Scripts/Core/CombatSession.cs`: assigned player health, ScooterController, ThirdPersonCamera, AutoLaser, four melee instances, and CombatView. Death disables those gameplay components, releases the cursor, and shows the panel. Retry is guarded against repeated requests.
- `Assets/Scripts/UI/CombatView.cs`: assigned HP Text, death panel, and Retry Button. The scene contains one Canvas and an EventSystem with InputSystemUIInputModule.
- `Assets/Art/M2/`: simple floor, wall, enemy, and unlit laser materials. No additional lights, particles, or external assets.

Player and enemy geometry use built-in layer 2 (`Ignore Raycast`). Combat selects enemies through its registry, independently of physics raycast layers. Environment geometry uses layer 0 (`Default`), which is included in laser, contact-occlusion, and camera obstruction checks. No project layer settings were changed. When integrating elsewhere, assign an environment mask excluding players/enemies; melee wall checks currently use `Default` explicitly.

The scene includes exactly one camera, Audio Listener, and directional light. All added assets and folders have `.meta` files generated by the pinned Editor in an isolated project copy; existing GUIDs were preserved.

## Reproduce Checks and Build

**Boki → Run M2 Smoke Checks** opens the combat scene, enters Play Mode, tests it, and exits Play Mode. Save open scenes first: the runner refuses dirty scenes. Temporary test positions, damage, and wall geometry are not saved. Success logs `M2_SMOKE_PASSED`.

For an isolated terminal run:

```text
<unity-6000.6.7f1> -batchmode -nographics -job-worker-count 2 -projectPath <isolated-project> -executeMethod Boki.Editor.M2SmokeChecks.Run -logFile <log-path>
```

Do not add `-quit`; the smoke runner exits when finished. Run EditMode tests through Test Runner, or use `-runTests -testPlatform EditMode -testResults <xml-path>` in batch mode.

**Boki → Create M2 Combat Arena** is a creation utility, not a reset command. It refuses to overwrite the delivered scene or enemy prefab and preserves the previously active scene.

**Boki → Build M2 Linux Test Player** and **Boki → Build M2 Windows Test Player** create development players using an explicit combat-scene list. Choose an output folder outside tracked assets. These commands do not edit shared build profiles or Editor build settings. For batch builds, set `BOKI_M2_BUILD_DIRECTORY` and invoke `Boki.Editor.M2PlayerBuild.Linux` or `.Windows`. Install the matching platform support in the pinned Editor first.

Play Mode retry loads the saved scene directly through the Editor API; player retry uses SceneManager. A build made another way must include `Combat_Test.unity` in its scene list.

## Validation Results

Unity **6000.6.7f1**, Linux, isolated project, batch mode with graphics disabled:

- Nine EditMode health tests passed: initial HP, invalid maxima, non-positive damage, nonlethal damage, lethal/overkill damage, repeated damage, and reentrant notification safety.
- Runtime and Editor scripts compiled; scene and prefab were generated and imported by Unity.
- Play Mode smoke checks passed for out-of-range and disabled targets, nearest visible selection, wall occlusion, extra-collider handling, an actual automatic kill, melee damage cooldown, death shutdown, unlocked death UI, and three successive UI-button retries.
- Every retry restored 100 HP, four enemies, one camera, enabled movement/camera/laser, and hidden death UI.
- Existing M1 smoke checks passed with M2 present: saved references, grounding, wall collision, camera obstruction, and 120 Play Mode frames.
- A Linux x86_64 development player built successfully with the combat scene supplied explicitly. An eight-second headless startup run logged no errors and was ended by a timeout; this checks startup only, not rendered visuals, player UI interaction, or performance. Output: `/tmp/boki-m2-player/Boki-M2.x86_64` (local temporary artifact).
- Unity Test Framework was already resolved transitively; no package change was necessary.
- The first EditMode run completed all nine tests successfully, then hit a native Unity shutdown crash. Repeating with `-job-worker-count 2` passed and exited cleanly; scene generation and M2 smoke checks also exited cleanly with that setting.

The developer confirmed manual gameplay acceptance after playtesting. Individual frame-rate comparisons and focus-change checks were not separately reported; the automated smoke check does not establish those behaviors or game balance. Existing M1 movement/camera code and assets remain unchanged.

Windows support is not installed in this Linux Editor. A Windows x86_64 build and actual playtest at 1280×720 Low on the Ryzen 5600G remain pending; no Windows compatibility or performance result is claimed.
