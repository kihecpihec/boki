# M5 Implementation Plan: Permanent C Unlocks

Status: implemented on `feat/m5-persistent-unlocks`; see [M5 handoff and verification](M5-verification.md) for validation and remaining acceptance.

Deliver M5 from [Architecture §9](../Architecture.md#9-development-milestones): earn permanent C-route access at level milestones, save immediately, and apply it only when the next run begins. Preserve the canonical [route matrix and saving rules](../Gameplay.md#2-branching-route-graph), the M1/M2 baselines, and M4's branch isolation.

## Scope and Ownership

The developer explicitly authorized ownership and updates to all three M4 level scenes for playable C paths and milestone wiring. Keep their GUIDs, existing A/B routes, and prefab references. Leave M1–M3 scenes, existing prefabs, project settings, input assets, and build settings unchanged. Work on the feature branch; commits, pushes, and merges require a separate explicit request.

M6 retains ranged enemies, light/battery behavior, Guilt, boss startup/combat, and the functional `POWER OFF` panel. No main menu, upgrades, unlock cheat, save reset UI, or visual polish is needed for M5.

## Implementation

1. Add a small deterministic `PersistentUnlocks` service with an injectable store. Use a Unity adapter with the three explicit PlayerPrefs keys from [Architecture §4](../Architecture.md#4-runtime-state). Read absent/invalid flags as locked. Write only the earned key and call `PlayerPrefs.Save()` immediately; repeated milestones must not repeat writes or saves.
2. Determine production persistence from the existing Pohorje entry destination, including scenes cached before M5. Do not require a new Inspector opt-in. Preserve the standalone M3 in-memory demonstration. Read saved flags on session initialization and every Retry/Start New Run, copying them into `RunState.AvailableUnlocks`. Never mutate the active snapshot when a flag is earned.
3. Validate living player, active level, chosen route, destination, and transition guard before awarding Forest/City progress. Save before advancing/loading. Arena entry requires a living player with a FERI choice and is accepted once per run; it earns FERI C without claiming victory or starting a boss.
4. Remove the reserved C wall from each owned scene and supply a short tunnel/service lane on the existing floor. Keep primitive collision geometry, route dividers, entrance and rear seals, and selected-only encounter behavior. An empty C encounter root is acceptable; do not create extra enemy systems solely for this slice.
5. Provide an idempotent Editor upgrade helper that refuses Play Mode or dirty scenes, preserves scene GUIDs, and restores the previous scene setup. Provide an explicit three-scene M5 build helper without changing shared build settings.
6. Add deterministic tests for defaults, partial progress, all milestones, duplicate/stale/dead/invalid requests, snapshot isolation, new-run reset, and route-lock priority after unlocking. Exercise the actual PlayerPrefs adapter across separate Editor processes in an isolated preferences namespace.
7. Exercise saved scene gates, real exit/arrival triggers, A/B regression histories and C histories, HP carry, rear seals, encounter activation, and controller traversal. Generate all new metadata with Unity **6000.6.7f1**.
